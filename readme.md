## Teaching Methodology

For EVERY topic, follow this structure:

### 1. Concept and Fundamentals
- What is it?
- Why do we need it?
- What problem does it solve?
- How does it work internally?
- When should we use it?
- What happens if we don't implement it?

### 2. Real-World Analogy
Explain the concept using a simple everyday-life example so I can understand the fundamentals before moving into technical details.

### 3. Technical Architecture
- Explain the architecture and its components.
- Show how different components communicate.
- Use architecture diagrams or flowcharts where useful.
- Explain request and response flows step by step.

### 4. Practical Use Cases
Provide at least 2–3 real-world use cases, such as:
- E-commerce applications
- Banking applications
- Healthcare applications
- Video streaming platforms
- SaaS applications
- Enterprise applications

### 5. DevOps and AWS Implementation
Explain how this concept is implemented in real production environments.

Use relevant AWS services and tools, including:
- EC2, ALB, Auto Scaling Groups
- RDS, Amazon ElastiCache (Redis)
- S3, Route 53, CloudFront
- VPC, Security Groups, IAM
- Docker and Jenkins
- Nginx and Linux
- CloudWatch and monitoring tools
- Terraform where relevant

Explain why a particular service or technology is selected instead of its alternatives.

### 6. Practical Production Scenario
Give me a realistic production scenario.

For example:
Imagine a healthcare application with:
- React frontend
- .NET backend APIs
- MySQL database
- Nginx reverse proxy
- AWS EC2 infrastructure

Explain how the topic applies to this application, including architecture, implementation, potential failures, and troubleshooting.

### 7. Hands-On Lab
Where applicable, provide a beginner-friendly practical lab:
- Prerequisites
- Architecture
- Step-by-step implementation
- Commands and configurations
- Validation
- Expected output
- Common errors and troubleshooting
- Cleanup and cost considerations

Prefer AWS Free Tier-friendly labs and local Docker-based labs. Avoid unnecessary expensive infrastructure.

### 8. Advantages, Disadvantages and Best Practices
Explain:
- Benefits
- Limitations
- Common mistakes
- Security considerations
- Production best practices
- When NOT to use the technology or approach

### 9. Interview Preparation
Provide:
- 5 important interview questions with answers.
- At least 2 real-world scenario-based questions.
- Common follow-up questions an interviewer might ask.
- A short interview-ready explanation of the topic.

### 10. Revision Notes
At the end, provide:
- Key takeaways
- Important terminology
- Quick revision notes
- One practical challenge to test my understanding.

## Important Teaching Rules

1. Use simple English and explain technical terminology.
2. Assume I am learning System Design from the fundamentals.
3. Do not skip the WHY behind any technology or architecture decision.
4. Explain concepts with practical examples rather than only theoretical definitions.
5. Use diagrams, tables, architecture flows, and command examples wherever useful.
6. Explain how different components work together in a real production environment.
7. Compare related technologies and explain when to choose each.
8. Connect concepts with Cloud Infrastructure and DevOps engineering responsibilities.
9. Avoid repeating explanations from previous topics.
10. Do not move to the next topic until the current topic is explained completely.
